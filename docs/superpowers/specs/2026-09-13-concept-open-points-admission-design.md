# Concept close-out: open-points admission gate + hand-offs — design

**Date:** 2026-09-13 · **Skill:** `plugins/devops/skills/concept` · **Status:** implemented in the same PR

## Problem

Two things about the final report's close-out made it a nuisance in real use:

1. **The "Offene Punkte" list became a closing ritual.** Every report ended
   with a few follow-ups, and too many were either the obvious next step of
   the scope the user had just approved ("Phase 4" after they clicked
   implement on a plan that contained phase 4) or a generic best-practice
   nudge. Each row asks the user for a decision they never asked to make,
   and an in-scope leftover on that list turns a shortfall into a request for
   the user's signature.
2. **The steps the user has to take by hand after the merge vanished.** They
   were one more paragraph ("Nächste Schritte") among the others, unmarked in
   the TOC and absent from the panel where the close-out happens — the one
   part of the report that turns into a to-do for a person was the least
   visible one.

The three-route toggle per open point (Issue / Jetzt umsetzen / Ignorieren)
already existed since #360 (v0.151); the page that surfaced the problem was
generated by a 0.149 plugin still running the old wizard.

## Design

### Admission gate (default: no section)

`SKILL.md` § "Open points section — admission gate" replaces "when to
include". Exactly two origins are admissible, declared per item as
`data-oq-origin`:

| Origin | Value | Qualifies |
|---|---|---|
| Deferred by the user | `deferred` | The user explicitly parked it during this concept (comment, rejected-for-now variant, card answered "aufschieben"); the body names where. |
| Found on the way | `found` | Surfaced during implementation, no or at most a remote relation to the scope, would be lost otherwise. |

Never an open point: anything in the approved scope (built, or reported as a
shortfall in Zusammenfassung / Tests), the no-brainer next step of the scope,
generic nudges, reality-check drift that broke nothing. Self-check: *would the
user be surprised to see this here?* — an expected row is scope or a new
concept. No survivor → no section, no stub.

The implement branch gains the matching rule: **the approved scope is built
in full**; nothing accepted may be deferred into the open points.

### Origin on the sheet row

`buildFollowUpList()` renders a muted tag (`.followup-origin`, locale
`final.origin_deferred` "bewusst vertagt" / `final.origin_found` "unterwegs
gefunden") between the title and the three routes. It is context for the
route decision, not a fourth choice; a row without an admissible origin gets
no tag. Validation gate **33b** hard-fails a final report whose open-point
checkboxes lack the attribute; a report without the block passes — the
normal case.

### Hand-offs ("Danach von Hand")

`<section id="handoffs" data-nav-label="{{final.handoffs}}" data-handoffs>`
replaces the "Nächste Schritte" recommendation slot and exists only when the
user has to do something by hand after the merge. Three places paint it:

- **Report body** — warning-coloured callout with a ⚠ heading.
- **TOC** — `buildSectionNav()` stamps `data-handoffs` on the entry; CSS gives
  it the warning colour and a ⚠ marker in every scroll position.
- **Close-out sheet** — a `handoffs` block (`renderHandoffs()`) mirrors the
  list below the plan, directly above the execute button, and is the **only
  block that stays visible after `data-closed`**: the sheet's done state is
  "Concept abgeschlossen" plus whatever is left for the user.

Validation gate **37b** requires the sheet block, and — when the report has
the section — `data-nav-label` plus at least one `<li>`.

### Out of scope, deliberately

- **Guided step-by-step close-out instead of one sheet.** The user's remark
  ("Alles ausführen ist unnötig, man sollte durch die Punkte geführt
  werden") was made against the 0.149 wizard, which showed a per-step
  "Weiter" *and* a global "Alles ausführen". The current sheet has exactly
  one commit. Whether the sheet should force an explicit answer on every
  block, or become guided again, is a panel-layout decision and goes to the
  panel concept that follows this PR.
