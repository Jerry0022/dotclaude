## What round 2 must show — four topic designs

1. **Full v2 — geführt** (revise round 1's Full; main design):
   - Stage layout: decision ≈ 66 % of the space incl. the question (big, calm, few elements, LARGE controls — no tiny buttons; must stay clear at "Entscheidung 10/17"); analysis ≈ 33 % as a side/companion column.
   - Analysis in **three levels**, always visible as a stack: L1 general results · L2 category/aggregated topic of the current group · L3 this single decision. Default: all three SHORT, except the level the user is on, which is LONG. Long = with one display type from the palette (a graphic, filled in a slimmed-down way), never full screen. Show the stack on the briefing (L1 long), on a category intro (L2 long) and on a decision stage (L3 long) so the user sees the rule work. Collapsible/expandable by click.
   - Stepper bar kept, now **clickable with tooltips** (hover shows decision title + state). Remove the top-right counters ("1 Abweichung" etc.).
   - No "☰ Liste" button; list mode, if at all, as a quiet text link below the stage elements.
   - No visible type chip ("Wählen"); keep at most 2 small labels per decision (e.g. "Gilt für: …" and the recommendation); say in an annotation what was cut.
   - Timing ("Welle 1/2/3/eigener PR") is NEVER a decision. Default = implement now. Offer a discreet text link "Als Issue anlegen (ggf. mit Epic)" per decision instead.
   - Use a real palette display type on the stage chart (name it in a small caption like "Darstellung: Ranked Dot Plot").
   - Keep review step and next-round card, slimmed to match.

2. **Kurz vs. lang — Erörterung** (new topic, the user explicitly asked to discuss it): one screen per level (L1, L2, L3) showing SHORT and LONG side by side with concrete content, plus a definition table (short = e.g. 1 sentence + 1 KPI/sparkline, max ~3 lines; long = display type + 2–4 sentences + evidence link; numbers are your proposal). Put the open questions as annotation pins with 2–3 concrete options and a recommendation each (e.g. "Kurz = 1 Satz oder 1 Satz + Mini-Grafik?", "Darf lang scrollen oder fixe Höhe?", "L1 nach dem Briefing automatisch auf kurz?").

3. **Darstellungs-Palette** (new topic): a catalogue of **≥ 30 display types** grouped by content shape (Messwert/Ziel, Verteilung, Rangfolge, Vergleich, Zeit/Verlauf, Zusammenhang/Matrix, Struktur/Hierarchie, Prozess/Fluss, Zustand/Status, Text-nahe Formen, …). Each type: a small live thumbnail (inline SVG/CSS), name, one-line "Nimm sie, wenn …" / "Nicht, wenn …" description written for Claude. Text is part of many types (annotated chart, callout + KPI, quote card, …), but there is exactly **ONE pure formatted-text type** ("Formatierter Text"). Plus a short style-rule block that lets Claude build its own type when none fits (tokens, max colours, labelling, dark/light, accessibility, size budget for the short/long slots). Make it browsable (filter chips by content shape) inside the mock.

4. **Entscheidungsmodi** (replaces round 1's "Bausteine"): **7 decision modes**, each live and clickable in the mock, with a "Wann Claude ihn einsetzt" line, the outcome-label rule and one real example question. Proposed set (adjust if better): Einzelwahl (Radio-Karten) · Mehrfachauswahl (Checkliste) · Ja / Nein / Anders (approve with alternative) · Schieberegler über einen Balken (Wert/Schwelle) · Reihenfolge (Drag-Sortierung) · Prüfen (stimmt / teilweise / stimmt nicht) · Freitext-Wahl (Benennen/Wording mit Vorschlägen). No "Freigabe jetzt/später/nein" timing mode (see feedback). Keep the anatomy screen and the before/after rewrites from round 1 but strip the corpus stats bar.
